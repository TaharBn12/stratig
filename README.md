# 🤖 Stratig — بوت تليجرام لتداول العقود الآجلة (Binance Testnet / Bybit)

استراتيجية **RSI + Williams %R** مع **تأكيد مزدوج**، تعمل على عقود USDT-M الآجلة،
ويتحكم بها **بوت تليجرام في وضع يدوي**: البوت يفحص السوق، يرسل لك الإشارة،
**وأنت تضغط ✅ للفتح أو ❌ للتجاهل**.

> ⚠️ **تنبيه**: هذا المشروع للتعلّم والتجربة. التداول بالرافعة المالية يضاعف الخسارة
> كما يضاعف الربح. ابدأ دائماً على **التيستنت** (أموال وهمية) وتحمّل مسؤولية قراراتك.

1. ادخل إلى https://testnet.binancefuture.com وسجّل بحساب جوجل/فيسبوك.

3. احتفظ بـ **API Key** و **Secret Key**.
4. (اختياري) اطلب رصيداً تجريبياً من الزر **Deposit / Faucet** داخل التيستنت.

### 2) بوت تليجرام
1. افتح [@BotFather](https://t.me/BotFather) ← `/newbot` ← اختر اسماً واسم مستخدم.
2. انسخ **التوكن**.
3. أرسل `/start` للبوت، ثم أرسل `/id` لتعرف معرّفك (chat id) — أو استخدم [@userinfobot](https://t.me/userinfobot).

### 3) ملف البيئة
```bash
cp .env.example .env
```


### 4) التثبيت

## 🕒 خطأ ‎-1021‎: «Timestamp … ahead of the server's time»

```json
(400, -1021, "Timestamp for this request was 1000ms ahead of the server's time.")
```

Binance **ترفض أي طلب توقيته في المستقبل** بأكثر من ~1 ثانية، حتى لو كان
`recvWindow` كبيراً. السبب دائماً: ساعة جهازك متقدّمة أو منحرفة عن التوقيت العالمي.

### الحماية المدمجة (تلقائية، لا تحتاج تدخّلاً)
| الطبقة | ماذا تفعل |
|---|---|
| 1. قياس الفرق | يجلب توقيت المنصة عند الإقلاع وكل **30 دقيقة** |
| 2. ترقيع الموصّل | كل طلبات Binance (أوامر/رصيد/صفقات) تحمل التوقيت المُصحَّح، مع هامش أمان يجعلنا **متأخّرين قليلاً لا متقدّمين** |
| 3. إعادة المحاولة | عند ظهور ‎-1021‎ يُزامن فوراً ويعيد الطلب مرة واحدة |

### إصلاح الساعة نفسها (مُستحسن)
```bat
w32tm /resync          &&:: موجّه أوامر «كنمسؤول»
```
أو: الإعدادات ← الوقت واللغة ← **مزامنة الساعة الآن** + تفعيل «ضبط الوقت تلقائياً».

### تشخيص الانحراف
```bat
.venv\Scripts\python.exe scripts\fix_time.py
```
```
  توقيت جهازك : 2026-11-10 07:44:43 UTC
  توقيت المنصة: 2026-11-10 07:44:46 UTC
  الفرق: +3.200 ثانية (جهازك متأخّر)
✅ البوت يعوّض هذا الفرق تلقائياً
```
أو من تليجرام: `/data` → سطر «🕒 التوقيت».

## 📓 استراتيجية Scalping Modified I — مطبَّقة حرفياً

منقولة سطراً بسطر من `01_Strategy_Scalping_Modified_I.ipynb` بلا أي تغيير في الثوابت أو المنطق.

### المؤشرات (كانت `pandas_ta`، الآن حساب خالص ببايثون — بدون numpy/pandas)

| في الدفتر | هنا | الثوابت |
|---|---|---|
| `ta.ema(Close, length=50)` | `ema(close, 50)` | `EMA_slow = 50` |
| `ta.ema(Close, length=30)` | `ema(close, 30)` | `EMA_fast = 30` |
| `ta.rsi(Close, length=10)` | `rsi(close, 10)` | للعرض فقط (الدفتر علّق استخدامه) |
| `ta.bbands(Close, length=15, std=1.5)` | `bbands(close, 15, 1.5, ddof=1)` | `BB_LENGTH=15`، `BB_STD=1.5` |
| `ta.atr(High, Low, Close, length=7)` | `atr(h, l, c, 7, mode="rma")` | `ATR_LENGTH=7` |

### قواعد الدخول (كما في الدفتر تماماً)

```python
# EMA Signal — النافذة [current-7, current) لا تشمل الشمعة الحالية
if   all(EMA_fast < EMA_slow): trend = 1      # هابط
elif all(EMA_fast > EMA_slow): trend = 2      # صاعد

# Total Signal
trend == 2 and Close <= BBL  →  شراء (long)
trend == 1 and Close >= BBU  →  بيع  (short)
```

### المخارج (من صنف `MyStrat` في الدفتر)
```
slcoef = 1.1        TPSLRatio = 1.5
شراء: SL = Close − 1.1×ATR   TP = Close + 1.1×ATR×1.5
بيع : SL = Close + 1.1×ATR   TP = Close − 1.1×ATR×1.5
```
أي **العائد : المخاطرة = 1.5 : 1** دائماً.

### تفاصيل دقيقة حوفظ عليها
- نافذة الاتجاه `iloc[start:end]` **حصرية** → آخر 7 شموع قبل الحالية.
- الانحراف المعياري لبولينجر بـ `ddof=1` (سلوك `pandas_ta` التلقائي = الانحراف المعياري للعيّنة).
- `ATR` بتنعيم `rma` كما يعرّفه `pandas_ta` (يتطابق مع الحساب الخالص بفارق ~1e-12).
- حجم الصفقة في الدفتر `mysize = 3000` وحدة للاختبار الخلفي؛ أما البوت فيستخدم `trade.qty_usdt` (قيمة بالدولار).

### تحقّق من القيم بنفسك
```bat
.venv\Scripts\python.exe scripts\strategy_check.py BTCUSDT --strategy scalping_i
```
يعرض EMA/بولينجر/ATR/RSI على آخر 3 شموع حقيقية + الإشارة + أسعار الوقف والهدف،
لتقارنها مع TradingView.

> اختبار آلي (`tests/test_scalping_i.py`) يعيد تنفيذ منطق الدفتر كاملاً بـ pandas
> ويقارنه شمعة بشمعة مع نسختنا الخالصة — ويتخطّى نفسه إن لم تكن pandas مثبّتة.

## ⏱ تغيير الإطار الزمني (ولماذا لا يتغيّر أحياناً)

```
/tf 5m          ← الأسرع
/set tf 1h
```

| الصيغة المقبولة | النتيجة |
|---|---|
| `5` · `5m` · `5min` · `5M` | `5m` |
| `15` · `30` | `15m` · `30m` |
| **`4`** · `6` · `8` · `12` · `24` | **`4h`** · `6h` · `8h` · `12h` · `1d` |
| `1h` · `1H` · `1hour` · `60` | `1h` |
| `4h` · `240` · `1d` · `1day` · `1w` · `1M` (شهر) | كما هي |

> الرقم العارٍ يُقرأ **دقائق** إن كان إطار دقائق مقبولاً (`5` → `5m`)،
> وإلا **ساعات** (`4` → `4h`، `24` → `1d`) — لأن `4m` و`24m` غير موجودين أصلاً.

الإطارات المسموحة: `1m 3m 5m 15m 30m 1h 2h 4h 6h 8h 12h 1d 3d 1w 1M`

**وقيمة خاطئة لا توقف البوت أبداً:** تُصحَّح تلقائياً ويستمر التشغيل مع تحذير واضح:
```
تحذير | تم توحيد الإطار الزمني: 4 → 4h
تحذير | الإطار الزمني "7m" غير مدعوم — تم استخدام 15m بدلاً منه واستمر البوت.
        المسموح: 1m, 3m, 5m, 15m, 30m, 1h, 2h, 4h, 6h, 8h, 12h, 1d, 3d, 1w, 1M
```
ويُكتب التصحيح في `config.toml` حتى لا يتكرر.

### لماذا قد يبدو أن الإطار «لا يتغيّر»؟

| السبب | الحل (مُعالَج في هذا الإصدار) |
|---|---|
| **فترة السمومية** (`cooldown_seconds = 1800`): الرموز التي أعطت إشارة كانت مستثناة 30 دقيقة، فلا يظهر أثر الإطار الجديد | ✅ `/tf` **يمسح السمومية تلقائياً** في نفس اللحظة |
| **تعديل `config.toml` يدوياً أثناء عمل البوت**: الإعدادات كانت تُقرأ مرة واحدة عند الإقلاع | ✅ `/reload` — أو **تلقائياً**: يفحص البوت تغيّر الملف في كل دورة فحص ويعيد قراءته |
| **إطار مرفوض** (`7m` مثلاً): تفشل كل طلبات الشموع ويُسجَّل الخطأ في `DEBUG` فقط، فلا تظهر أي إشارة ولا أي خطأ | ✅ يُرفض عند الإدخال + إن فشل **كل** الرموز يظهر تنبيه صريح في السجل وتليجرام |
| لا توجد إشارة أصلاً على الإطار الجديد | طبيعي — جرّب `/set both false` أو `/scanall` |

تحقّق من الإطار الفعّال الآن:
- `/tf` (بدون قيمة) → الإطار الحالي + عدد الرموز داخل السمومية
- `/status` → سطر `الإطار الزمني`
- `/settings` → `strategy.timeframe`

## 🧪 المحاكاة أم تنفيذ حقيقي؟ (ولماذا لا تُنفَّذ أوامري؟)

ثلاثة مستويات مختلفة تماماً — الخلط بينها هو أشهر سبب لرسالة
«🧪 محاكاة — لم تُرسل أمراً حقيقياً»:

| المستوى | الإعداد | ماذا يحدث عند ضغط ✅ |
|---|---|---|
| 🧪 **محاكاة** (`dry_run`) | `safety.dry_run = true` | **لا يُرسل أي أمر** — تحليل فقط |
| 🧪 **تيستنت** | `TESTNET=true` في `.env` | يُرسل أمر **حقيقي** إلى محرك Binance التجريبي، لكن **الأموال وهمية** |
| 🔴 **حقيقي** | `TESTNET=false` + `CONFIRM_LIVE_TRADING=1` | أمر حقيقي بأموال حقيقية |

### أريد التنفيذ الحقيقي الآن
أرسل للبوت (أو اضغط زر **🔴 تنفيذ حقيقي**):
```
/live
```
يُطبَّق **فوراً** على الجلسة (بدون إعادة تشغيل) ويُحفظ في `config.toml`،
وترى بعدها في كل إشارة: `🔴 عند التأكيد يُرسل أمر حقيقي إلى binance-testnet`.

للعودة للمحاكاة: `/dryrun`

### أو عدّل الملف يدوياً
```toml
[safety]
dry_run = false        # false = نفّذ أوامر حقيقية
```

### إن استمرت المحاكاة بعد `/live`
القيمة تُقرأ بهذا الترتيب (الأقوى أخيراً)، وسيخبرك السجل بالمصدر:
1. `config.toml` → `safety.dry_run`
2. متغير البيئة `DRY_RUN` (إن وُجد في `.env`)
3. إقلاع البوت بـ `run.bat --dry-run`

> ⚠️ `safety.dry_run` يمنع **الأوامر فقط**. أما `TESTNET=true` فالأوامر تُنفَّذ
> فعلاً لكن على التيستنت بأموال وهمية — وهو الأنسب للتجربة.

## 🧠 الاستراتيجية

### RSI (مؤشر القوة النسبية)
```
شراء:  RSI[-3] < 30  و  RSI[-2] < 30  و  RSI[-1] > 30   (اختراق صاعد من تشبّع بيعي)
بيع:   RSI[-3] > 70  و  RSI[-2] > 70  و  RSI[-1] < 70   (كسر هابط من تشبّع شرائي)
```

### Williams %R
```
شراء:  W%R < -99.5                                   (تشبّع بيعي شديد)
       أو  W%R < -75 ويتقاطع صاعداً فوق EMA(24)
بيع:   W%R > -0.5                                    (تشبّع شرائي شديد)
       أو  W%R > -25 ويتقاطع هابطاً تحت EMA(24)
```

### الدمج (التأكيد المزدوج)
`strategy.require_both: true` → **يجب** أن يتفق المؤشران، وأي تعارض يُلغي الصفقة.

### حماية الصفقة
- TP/SL تُوضع كأوامر `TAKE_PROFIT_MARKET` / `STOP_MARKET` مع `closePosition=true`
  (أي تغلق كامل الصفقة تلقائياً عند التحقيق).
- إن فشل وضع **وقف الخسارة** → يُغلق المركز فوراً حمايةً للمال.

> ⚠️ **تغيير Binance (ساري منذ 2025-12-09):** الأوامر الشرطية انتقلت من
> `POST /fapi/v1/order` إلى **`POST /fapi/v1/algoOrder`**، واسم حقل سعر
> الإطلاق تغيّر من `stopPrice` إلى **`triggerPrice`**. الإرسال للنقطة القديمة
> يُرجع `-4120 Order type not supported for this endpoint` وتُفتح الصفقة
> بلا حماية. هذا المشروع يستخدم النقطة الجديدة (مع محاولة احتياطية
> بـ `quantity + reduceOnly` إن رُفض `closePosition`)، ويلغي الأوامر الشرطية
> عبر `DELETE /fapi/v1/algoOrder` عند إغلاق الصفقة حتى لا تُفتح صفقة لاحقاً
> بالخطأ. للتحقق بنفسك: `/protect` أو
> `.venv\Scripts\python.exe scripts\check_protection.py`

### أهم الإعدادات (config.toml)
| المسار | الافتراضي | المعنى |
|---|---|---|
| `strategy.timeframe` | `15m` | الإطار الزمني |

| `risk.max_positions` | `5` | أقصى صفقات مفتوحة |
| `scanner.interval_seconds` | `120` | كل كم يفحص البوت |

## 🆘 استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| `مفاتيح API غير مضبوطة` | املأ `.env` ثم `python main.py --check` |
| البوت لا يرد | تأكد من التوكن، وأن معرّفك داخل `TELEGRAM_CHAT_IDS` (أو اتركه فارغاً) |
| لا تصل إشارات | أرسل `/start` للبوت أولاً، وتأكد أن الفحص يعمل (`/status` → يعمل 🟢) |
| `الحد الأدنى لقيمة الصفقة` | ارفع `trade.qty_usdt` (Binance يرفض أقل من ~20 USDT) |
| لا إشارات لفترة طويلة | طبيعي — التأكيد المزدوج نادر. جرّب `/set tf 5m` أو `/set both false` |
| `(-1021) Timestamp for this request was 1000ms ahead` | **مُعالَج تلقائياً**: البوت يزامن توقيته مع المنصة ويعيد المحاولة. واصل إصلاح ساعة ويندوز: `w32tm /resync` (كمسؤول) — والفحص: `scripts/fix_time.py` |
| `DLL load failed` مع numpy/pandas | **مُصلح**: لم تعد المشروع يستخدمهما — حدّث بـ `update.bat` ثم احذف `.venv` وأعد `setup.bat` |
| `PTBUserWarning: No JobQueue set up` | الفحص التلقائي لن يعمل. أعد تشغيل `setup.bat` لتثبيت `apscheduler` (وإلا يعمل البوت بحلقة فحص داخلية بديلة) |
| `(-4120) Order type not supported for this endpoint` | **مُصلح**: نقلت Binance الأوامر الشرطية إلى نقطة Algo — حدّث بـ `update.bat` |
| `Can't parse entities: unsupported start tag` | **مُصلح**: رموز `<` و `>` في أسباب المؤشرات تُهرَّب الآن، وإن فشل التنسيق يُعاد الإرسال كنص عادي |
| `maximum number of running instances reached` | مجرد تحذير: دورة فحص سابقة لم تنتهِ. ارفع المدة بـ `/set interval 300` |
| `الإطار الزمني "..." غير مدعوم` | **مُصلح**: يُصحَّح تلقائياً (`4` → `4h`) ويستمر البوت — لم يعد يرفض التشغيل |
