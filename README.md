# 🤖 Stratig — بوت تليجرام لتداول العقود الآجلة (Binance Testnet / Bybit)

استراتيجية **RSI + Williams %R** مع **تأكيد مزدوج**، تعمل على عقود USDT-M الآجلة،
ويتحكم بها **بوت تليجرام في وضع يدوي**: البوت يفحص السوق، يرسل لك الإشارة،
**وأنت تضغط ✅ للفتح أو ❌ للتجاهل**.

> ⚠️ **تنبيه**: هذا المشروع للتعلّم والتجربة. التداول بالرافعة المالية يضاعف الخسارة
> كما يضاعف الربح. ابدأ دائماً على **التيستنت** (أموال وهمية) وتحمّل مسؤولية قراراتك.

## 🚀 التشغيل السريع (Binance Testnet)

### 1) مفاتيح Binance التجريبية
1. ادخل إلى https://testnet.binancefuture.com وسجّل بحساب جوجل/فيسبوك.
2. من قائمة **API Key** أنشئ مفتاحاً جديداً (HMAC).
3. احتفظ بـ **API Key** و **Secret Key**.
4. (اختياري) اطلب رصيداً تجريبياً من الزر **Deposit / Faucet** داخل التيستنت.

### 2) بوت تليجرام
1. افتح [@BotFather](https://t.me/BotFather) ← `/newbot` ← اختر اسماً واسم مستخدم.
2. انسخ **التوكن**.
3. أرسل `/start` للبوت، ثم أرسل `/id` لتعرف معرّفك (chat id) — أو استخدم [@userinfobot](https://t.me/userinfobot).

### 3) ملف البيئة
```bash
cp .env.example .env
nano .env          # املأ القيم
```
```env
TELEGRAM_BOT_TOKEN=123456789:AAFxxxxxxxxxxxxxxxxxxxxxxxxxxxx
TELEGRAM_CHAT_IDS=123456789
EXCHANGE=binance
TESTNET=true
BINANCE_TESTNET_API_KEY=...
BINANCE_TESTNET_API_SECRET=...
```

### 4) التثبيت
```bash
python3 -m venv .venv
source .venv/bin/activate          # ويندوز: .venv\Scripts\activate
pip install -r requirements.txt
```
> **لا يحتاج أي مكتبة مترجَمة C/C++**: لا `numpy` ولا `pandas` ولا `PyYAML` ولا `ta` —
> وحتى `pycryptodome` (التي تطلبها مكتبة بينانس) يستمر المشروع بدونها ببديل وهمي،
> الإعدادات TOML (مكتبة قياسية)، الشموع في حاوية `list` بسيطة،
> والمؤشرات (RSI / Williams %R / EMA) محسوبة ببايثون خالص.
> هذا يتفادى أخطاء مثل `DLL load failed` و `Microsoft Visual C++ 14.0 is required`.

### 5) تحقّق ثم تشغيل
```bash
python main.py --check     # يتحقق من المفاتيح والاتصال (بدون تليجرام)
python main.py             # تشغيل البوت
```
افتح تليجرام وأرسل للبوت: `/start`

> تأكد في اللوج من ظهور: `تم جدولة الفحص التلقائي كل 120 ثانية`.
> إن ظهر بدلاً منها `No JobQueue set up` أعد تشغيل `setup.bat` لتثبيت `apscheduler`.

> جرّب أولاً: `python main.py --dry-run` (محاكاة كاملة بدون أوامر)،
> أو `python scripts/demo_scan.py` (عرض توضيحي على بيانات اصطناعية بدون إنترنت).

## 🕒 خطأ ‎-1021‎: «Timestamp … ahead of the server's time»

```json
(400, -1021, "Timestamp for this request was 1000ms ahead of the server's time.")
```

Binance **ترفض أي طلب توقيته في المستقبل** بأكثر من ~1 ثانية، حتى لو كان
`recvWindow` كبيراً. السبب دائماً: ساعة جهازك متقدّمة أو منحرفة عن التوقيت العالمي.

### الحماية المدمجة (تلقائية، لا تحتاج تدخّلاً)
| الطبقة | ماذا تفعل |
|---|---|
| 1. قياس الفرق | يجلب توقيت المنصة عند الإقلاع وكل **30 دقيقة** |
| 2. ترقيع الموصّل | كل طلبات Binance (أوامر/رصيد/صفقات) تحمل التوقيت المُصحَّح، مع هامش أمان يجعلنا **متأخّرين قليلاً لا متقدّمين** |
| 3. إعادة المحاولة | عند ظهور ‎-1021‎ يُزامن فوراً ويعيد الطلب مرة واحدة |

### إصلاح الساعة نفسها (مُستحسن)
```bat
w32tm /resync          &&:: موجّه أوامر «كنمسؤول»
```
أو: الإعدادات ← الوقت واللغة ← **مزامنة الساعة الآن** + تفعيل «ضبط الوقت تلقائياً».

### تشخيص الانحراف
```bat
.venv\Scripts\python.exe scripts\fix_time.py
```
```
  توقيت جهازك : 2026-11-10 07:44:43 UTC
  توقيت المنصة: 2026-11-10 07:44:46 UTC
  الفرق: +3.200 ثانية (جهازك متأخّر)
✅ البوت يعوّض هذا الفرق تلقائياً
```
أو من تليجرام: `/data` → سطر «🕒 التوقيت».

## 🧠 الاستراتيجيات والتبديل بينها

```bat
/strategy              ← يعرض القائمة بزرّ تبديل
/strategy scalping_i   ← تبديل فوري (يُطبَّق بلا إعادة تشغيل)
```

| المعرّف | الاسم | منطق الدخول | المخارج |
|---|---|---|---|
| `rsi_williams` | RSI + Williams %R (الأصلية) | تأكيد مزدوج: اختراق RSI من تشبّع + تقاطع W%R مع EMA | نسب ثابتة (`trade.*`) |
| `scalping_i` | **Scalping Modified I** (الدفتر الأول) | EMA 30/50 + بولينجر (15، 1.5) | **ATR**: وقف 1.1×ATR، هدف 1.5×الوقف |
| `mean_reversion_z` | ارتداد المتوسط (z-score) | يشتري إن هبط السعر عن متوسطه بـ 2 انحراف معياري | ATR |
| `rsi_reversion` | ارتداد RSI | تشبّع بيع/شراء بمؤشر واحد (أبسط ⇒ صفقات أكثر) | ATR |
| `donchian_breakout` | اختراق دونشيان | كسر أعلى/أدنى N شمعة (**بدون** الشمعة الحالية) | ATR |
| `ema_momentum` | زخم EMA | متوسط سريع فوق بطيء **و** السعر فوق السريع | ATR |

> الأربع الأخيرة خرجت من **مختبر الاستراتيجيات** (القسم أدناه). هي متاحة للتبديل
> والتجربة، لكنها **لم تعتمد**: لم يصمد أيٌّ منها أمام شروط القبول على البيانات
> التي جُرِّبت. استخدمها للتجربة، لا للتداول الحقيقي، حتى تراها تصمد على
> بياناتك أنت بـ `scripts/lab.py`.

التبديل يمسح فترة السمومية فوراً فتظهر إشارات الاستراتيجية الجديدة في الفحص القادم،
ويضبط `exit.mode` تلقائياً (`atr` للدفتر، `percent` للأصلية). يمكنك تجاوزه يدوياً بـ `/set exit percent`.

## 💡 «وما الحل؟» — مقياس الميزة

بعد كل القياسات (إدارة مخاطر، فلاتر جودة، مُحسِّن معاملات) يبقى السؤال:
**من أين تأتي الميزة أصلاً؟** الجواب من القياس لا من الحدس.

### القياس الحاسم: الاتجاه الصرف (بلا وقف ولا هدف)
`fwd3` = عائد 3 شموع بعد الإشارة **بلا أي مخارج** — أي ميزة الإشارة وحدها:

| الاستراتيجية | النظام | الاتجاه الصرف | الصفقات |
|---|---|---|---|
| `scalping_i` | جانبي | **−0.0010%** = صفر مطلق | 2065 |
| `scalping_i` | اتجاهي | +0.036% ≈ صفر | 412 |
| `rsi_williams` | جانبي | **+0.2019%** ✅ | 14 |
| `rsi_williams` | اتجاهي | **−0.4468%** ❌ | 46 |

### ومسح نسبة الهدف أثبت أنها **لا تصنع ميزة**
`scalping_i` مع كل النسب (نفس الإشارة، نفس العيّنة):

| نسبة الهدف | النجاح | التوقع |
|---|---|---|
| 1.0:1 | 44.2% | −0.247R ❌ |
| 1.5:1 | 34.3% | −0.277R ❌ |
| 2.0:1 | 29.6% | −0.258R ❌ |
| 3.0:1 | 22.0% | −0.301R ❌ |
| 5.0:1 | 17.0% | −0.303R ❌ |

> **الدرس**: نسبة الهدف تُضخّم ميزة موجودة، ولا تصنع ميزة من عدم.
> ومع نسبة 1.5:1 تحتاج 40% نجاح للتعادل — و`scalping_i` تحقّق **39.7%**.
> أي أن ميزتها **صفر بالضبط**، والعمولة (−0.15R) تجعلها خاسرة حتماً.

### ⚠️ تحذير من نتيجة مغرية
`rsi_williams` في النطاق الجانبي بدت رابحة — لكن **المولّد الاصطناعي للنطاق
الجانبي مرتدٌّ إلى المتوسط بالبناء** (`drift = log(anchor/price) × 0.02`)،
فهو **يُكافئ** استراتيجيات الارتداد ميكانيكياً. لا يجوز البناء عليها:
**قِس على بياناتك الحقيقية.**

### إذن ما الحل؟
ليس في المعاملات (أثبتنا أنها مبالغة في الملاءمة)، ولا في قلب الإشارة
(المعكوسة أسوأ). الحل الوحيد الصادق:

> **قِس الميزة قياساً إحصائياً، وتداول ما أثبت جدواه فقط.**

### 📊 مقياس الميزة — `/edge`
المتوسط وحده يخدع: **12 صفقة رابحة قد تكون حظاً**. لذلك يحسب المقياس
**فترة ثقة 95%** ويُصدر حكماً:

| الحالة | المعنى | القرار |
|---|---|---|
| ✅ **رابحة** | الفترة كلها فوق الصفر | تابع |
| ⛔ **خاسرة** | الفترة كلها تحت الصفر | **توقف** |
| ⚖️ غير حاسمة | الفترة تحتوي الصفر | لا حكم — لا نمنع |
| … لا بيانات | أقل من 30 صفقة | لا حكم — لا نمنع |

```
/set edgegate true     ← امنع التداول عند **ثبوت** الخسارة إحصائياً
/set edgemin 30        ← أدنى صفقات قبل إصدار حكم
/set edgelook 0        ← 0 = كل الصفقات، أو آخر N صفقة
```

> **لماذا لا نمنع عند «غير حاسمة»؟** لأن الفرق بين «لا ميزة مثبتة» و«خسارة
> مثبتة» جوهري: الأولى نقص دليل، والثانية دليل على الخسارة.

مثال حقيقي من تشغيل تجريبي:
```
✅ rsi_williams: رابحة · 34 صفقة · توقع +0.471R · بين +0.051R و +0.890R
⛔ scalping_i:  خاسرة · 62 صفقة · توقع −0.424R · بين −0.709R و −0.139R
⚖️ الإجمالي:    غير حاسمة · 96 صفقة (لا يُمنع)
```

هذا يختلف عن **قاطع الخسائر المتتالية**: ذاك يتفاعل مع سلسلة قصيرة،
وهذا يحكم على العيّنة كلها إحصائياً.

### ما الذي يصنع ميزة حقيقية إذن؟
بصدق، وبناءً على قياساتنا: **لم نجد ميزة بعد.** ما نملكه الآن هو:
1. **أدوات تمنع النزيف** (إدارة مخاطر + فلاتر جودة + بوابة الميزة)
2. **أداة تكشف الحقيقة** (`/edge` على صفقاتك الحقيقية، لا على الاصطناعية)
3. **أداة تمنع خداع الذات** (مُحسِّن يرفض المبالغة في الملاءمة)

خطوتك التالية: شغّل `/set edgegate true`، واجمع 30+ صفقة حقيقية،
ثم اقرأ `/edge`. الرقم هناك هو الحكم — لا رأيي ولا رأي أي أحد.

النطاق الجانبي كعملية **مرتدّة إلى المتوسط بالبناء** (`drift = log(anchor/price) × 0.02`)
— أي أنه يُكافئ استراتيجيات الارتداد ميكانيكياً، وكل نتيجة عليه **متحيّزة**.
الدراسة تجلب بيانات السوق الحقيقي من نقطة Binance العامة (بلا مفاتيح).

### الأسئلة الثلاثة

**1) الارتباط الذاتي للعوائد — الأهم**
| القيمة | المعنى |
|---|---|
| **سالب مهم** | السوق يرتدّ ⇒ استراتيجيات الارتداد لها أساس |
| **موجب مهم** | السوق يستمرّ ⇒ استراتيجيات الاتجاه لها أساس |
| ≈ صفر | **سير عشوائي ⇒ لا شيء يعمل**، وأي استراتيجية تدفع عمولة بلا مقابل |

العتبة `1.96/√n` — فالقيمة «مهمّة» فقط إن تجاوزتها.

**2) تشريح الشمعة** — يحدّد **أصغر وقف ممكن**: أي وقف أضيق من مدى الشمعة
الواحدة سيبتلعه الضجيج (وهو بالضبط ما يفسّر لماذا لا يعمل وقف 0.9% على 15m).

**3) اختبار الأنماط — مع تصحيح بونفيروني**
اختبار 6 أنماط بمستوى 95% يعطي **≈ 26%** احتمال أن يظهر أحدها «مهماً»
بالمصادفة البحتة. لذلك تُرفع العتبة من `1.96` إلى `2.64`.
> بلا هذا التصحيح، كل «دراسة أنماط» هي مطاردة ضجيج.

| النمط | الجهة المتوقّعة |
|---|---|
| مطرقة / ابتلاع شرائي / شمعة خضراء كبيرة | صعود |
| شهاب / ابتلاع بيعي / شمعة حمراء كبيرة | هبوط |
| داخلية / خارجية / دوجي | بلا جهة ⇒ تُقاس بـ**التقلّب** التالي |

### البوابات الثماني (كلها إلزامية، مرتّبة من الأرخص للأغلى)

| # | البوابة | السؤال الذي تجيب عنه |
|---|---|---|
| 1 | العيّنة ≥ 100 صفقة | دونها لا يمكنك تمييز ميزة من حظ |
| 2 | **بلا نظرة للمستقبل** | هل تتغيّر الإشارة إن حذفنا المستقبل؟ (اختبار إعادة الرسم) |
| 3 | خارج العينة > صفر | هل تصمد على آخر 30% من كل سلسلة؟ |
| 4 | الثبات ≥ 60% من النوافذ | هل تتكرّر أم تحملها نافذة واحدة؟ |
| 5 | تعدّد الأسواق ≥ 60% | هل تحملها عملة واحدة؟ |
| 6 | **أفضل من الدخول العشوائي** | أصعب بوابة: مونتي كارلو بنفس عدد الصفقات ونفس الوقف والهدف |
| 7 | فترة ثقة 95% (مصحّحة) | هل نستطيع نفي أنها خاسرة؟ |
| 8 | أقصى سحب ≤ 25R · عامل ربح > 1.1 | هل تُحتمل مخاطرتها؟ |

**البوابة السادسة هي الغائب الأكبر في أغلب الباك-تستات.** الدخول العشوائي
بهدف = 2×الوقف واتجاه عشوائي توقّعه ≈ صفر قبل التكلفة، و**سالب بعدها**
(عمولة + انزلاق بلا مقابل). فأي استراتيجية لا تتفوّق على القرعة هي بلا
قيمة — حتى لو كان توقّعها موجباً.

### ما تعلّمته هذه التجربة (أهم من الجدول)

**1. أعلى رقم في الجدول كاذب تماماً.** `rsi_williams · +اتجاه` حقّق **+1.178R**
خارج العينة — أعلى رقم في التجربة كلها — من **7 صفقات**. سبع. البوابة
الأولى وحدها أسقطته.

**2. الأخطر ليس الرقم السيّئ، بل الرقم الجميل المزيّف.** `rsi_reversion ·
+اتجاه` مرّ بأهم بوّابتين: خارج العينة **+0.405R** وثبات **78%**. لو اكتفيتَ
بهذين لحكمتَ أنها ممتازة. لكنها رابحة في **1 من 10 أسواق فقط** — وحين فحصنا
توزيع الصفقات: 10 إلى 24 صفقة لكل سوق، أي أن «النجاح» كله من سوق واحد
(SOL/15m). البوابة الخامسة كشفته.

**3. التشدد قلّل الضرر ولم يصنع ميزة.** الفلاتر خفّضت خسارة `scalping_i` من
‎−0.348R‎ إلى ‎−0.207R‎ وقلّصت السحب من 1256R إلى 694R — تحسّن حقيقي. لكنها
**لم تُوجب التوقع** في أي استراتيجية، وفي `mean_reversion_z` قلّلت العيّنة
من 3805 إلى 990 صفقة بلا تحسّن يُذكر. التشدد أداة ضبط، لا مصدر ميزة.

**4. استراتيجيتك الحالية ليست «سيّئة الحظ» — هي سالبة بثبات على كل الأسواق.**
`scalping_i` حقّقت ‎−0.348R‎ بعامل ربح 0.56 على 3500 صفقة. هذا ليس تشويشاً:
بعد 3500 صفقة، الإشارة واضحة.

| `sl` / `tp` | `0.02` / `0.04` | لإطار أعلى مع مخارج نسبية (لا تظهر مع مخارج ATR) |

### القاعدة الذهبية: التحقق خارج العينة
البحث في 100 تركيبة على نفس البيانات **سيجد** تركيبة رابحة بالمصادفة،
حتى على بيانات عشوائية. لذلك:

1. **يبحث على أول 70%** فقط من كل سلسلة
2. **يختبر الفائز على آخر 30%** التي لم ترها عملية البحث
3. **المشي للأمام** (`--folds`): نوافذ متتالية، ويرفض ما ربح في نافذة واحدة

### ماذا حدث فعلاً على بيانات اصطناعية
| الاستراتيجية | داخل العينة | **خارج العينة** | القرار |

| `rsi_williams` (40 محاولة) | −0.253R | 0 صفقات | ⛔ مرفوض |

> لاحظ الرقم الأخطر: **+0.373R مقابل أساس +0.082R** — تضاعف التوقع 4.5 مرة
> بلا أي تحسّن حقيقي، بل بمجرّد اختيار الأفضل من 80 محاولة.
> **هذا هو الفخ الذي يحميك منه `--folds`.**

### قراءة النتيجة
```

خارج العينة …R   ← الاحتفاظ 20%     ⛔ مبالغ في ملاءمتها

المشي للأمام: 1/4 نوافذ رابحة        ⚠️ طبّقها بحجم صغير وراقب أسبوعاً
```

> ⚠️ **تنبيه تقني مهم**: `sl_coef` و`tp_sl_ratio` لا تُؤثّران إلا مع
> `exit.mode = "atr"`. المُحسِّن يضبط هذا تلقائياً حسب الاستراتيجية.

## 🛡 إدارة المخاطر (مهمّة خصوصاً في الوضع التلقائي)

> المشكلة التي تعالجها: **إشارات كثيرة ضعيفة + تنفيذ تلقائي = نزيف**.
> قياسنا أظهر نجاحاً 40% مقابل تعادل 40% وعمولة 0.11–0.25R — أي أن الميزة
> الإجمالية ≈ صفر قبل الرسوم. إدارة المخاطر تمنع النزيف قبل تحسين الإشارة.

### 1) حجم الصفقة حسب التقلّب (الأهم)
```bat
/set sizing risk        ← الحجم يُحسب بحيث: الخسارة عند الوقف = riskpct × الرصيد
/set riskpct 0.01       ← 1% من الرصيد لكل صفقة
/set maxqty 300         ← سقف اختياري
```
الفرق: مع وقف 0.9% وآخر 3% كانت المخاطرة تختلف 3 أضعاف بين صفقتين. الآن ثابتة.

### 2) تحديد معدّل الدخول (يمنع الإفراط في التداول)
```bat
/set maxtrades 3        ← أقصى 3 صفقات في الساعة
/set mingap 900         ← فاصل 15 دقيقة بين صفقتين
```

### 3) قاطع الخسائر المتتالية
```bat
/set maxlosses 3        ← أوقف التداول بعد 3 خسائر متتالية
/set pauseloss 3600     ← لمدة ساعة (أو /resume للاستئناف فوراً)
```

### 4) إدارة الصفقة المفتوحة (اختياري — مُعطّل افتراضياً)
| الإعداد | المعنى |
|---|---|
| `risk.manage_positions` | تفعيل (يلغي الأمر الشرطي ويعيد وضعه) |
| `risk.breakeven_after_r` | بعد كم R يُنقل الوقف لنقطة التعادل (1.0) |
| `risk.breakeven_offset_pct` | هامش يغطّي العمولة (0.0006) |
| `risk.trailing` | وقف متحرك يتبع السعر |
| `risk.trail_distance_mult` | مسافة التتبّع = × مسافة الوقف الأصلية |
| `risk.max_hold_seconds` | أغلق الصفقة إن تجاوزت المدة (0 = معطّل) |

> **القاعدة الذهبية في الكود**: الوقف يتحرك في اتجاه واحد فقط — للأعلى في
> الشراء وللأسفل في البيع. لا يُسمح أبداً بإبعاده. مُختبر بـ `test_stop_never_moves_against_the_trade`.

نسبة النجاح، **التوقع بوحدة R**، **معامل الربح**، صافي الربح، أقصى سحب.
> التوقع الموجب مع معامل ربح > 1 هو الدليل الوحيد على أن الاستراتيجية تعمل.

## 📉 «أعطاني شراء فهبط، وأعطاني بيعاً فصعد» — هل الإشارة مقلوبة؟

**الجواب المختصر: لا. الكود غير مقلوب، لكن الاستراتيجيتين عكس-اتجاهيتان (mean-reversion) — تشتري الضعف وتبيع القوة.**

### ما تحقّقتُ منه أولاً (لا انعكاس في الكود)
| ما فُحص | النتيجة |
|---|---|
| ترتيب الشموع (Binance تصاعدي / Bybit تنازلي) | ✅ صحيح — وأضفنا ترتيباً زمنياً إجبارياً كحماية |
| اتجاه الوقف والهدف عند الشراء والبيع | ✅ `buy: SL تحت، TP فوق` — والعكس للبيع |
| جهة أمر الإغلاق (`close_side`) | ✅ `SELL` تُغلق شراءً و`BUY` تُغلق بيعاً |
| `positionSide` في وضع Hedge | ✅ `LONG` للشراء و`SHORT` للبيع |
| منطق RSI (خروج من تشبّع بيعي = شراء) | ✅ صحيح |
| منطق Williams %R (‎−100‎ قاع = شراء) | ✅ صحيح |
| ترميز الدفتر (`signal==2 → buy`) | ✅ مطابق |

### القياس — `scripts/backtest.py`
```bat
.venv\Scripts\python.exe scripts\backtest.py --synthetic --regime trend --series 10
.venv\Scripts\python.exe scripts\backtest.py                       (بيانات حقيقية)
.venv\Scripts\python.exe scripts\backtest.py --regime range --trend-filter
```

| الاستراتيجية | نظام السوق | الأصلية | **المعكوسة** | الاستنتاج |
|---|---|---|---|---|
| `rsi_williams` | **اتجاهي** | ‎−0.50R‎ | **+0.65R** | تخسر أمام الاتجاه |
| `rsi_williams` | **جانبي** | **+0.18R** | ‎−0.52R‎ | **سليمة تماماً** |
| `scalping_i` | اتجاهي | ‎−0.12R‎ | ‎−0.17R‎ | لا انعكاس (الأصلية أفضل) |
| `scalping_i` | جانبي | ‎−0.20R‎ | ‎−0.14R‎ | لا انعكاس |

**الانعكاس التامّ بين النظامين هو الدليل:** لو كان الكود مقلوباً لخسرت الاستراتيجية في النظامين معاً. هي تخسر في الاتجاهات فقط — لأنها تشتري الهبوط وتبيع الصعود.

### لماذا تخسر عملياً؟
1. **الوقف ضيّق جداً للإطار.** النسبة 2% / 0.9% على إطار 15m، وتقلّب الشمعة ≈ 0.4% → الوقف ≈ شمعتين ضجيج. نجاح التعادل عند R:R = 1.33 هو **43%**، والمقيس **19%**.
2. **العمولة.** round-trip taker على Binance ≈ 0.1% من القيمة → تكلفة **0.11R–0.25R** لكل صفقة. قياس `scalping_i`: نجاح 40.6% مقابل تعادل 40% → **الميزة الإجمالية ≈ صفر قبل العمولة**.
3. **الدخول المتأخّر.** الإشارة تُحسب عند إغلاق الشمعة، وأنت تؤكّد يدوياً (TTL 15 دقيقة) — أي قد تدخل بعد شمعة كاملة، وهو أسوأ توقيت ممكن لإشارة ارتدادية.

### ما أُضيف لمعالجة ذلك
| الإضافة | `/set` | الافتراضي |
|---|---|---|
| **عمر الإشارة وانحراف السعر** يظهران في رسالة الإشارة (طازجة 🟢 / تأخّرت 🟡 / متأخّرة 🔴) | — | دائماً |
| **حاجز الدخول المتأخّر**: ارفض/حذّر إن تحرّك السعر أكثر من `max_entry_drift` × الوقف | `drift` | تحذير |
| **منع الدخول المتأخّر** تماماً بدل التحذير | `block_stale` | `false` |
| **فلتر الاتجاه**: ارفض الإشارات المعاكسة لـ EMA | `trend` (`off`\|`ema`) | `off` |
| فترة EMA لفلتر الاتجاه | `trendperiod` | `200` |

> الفلتر **لا يغيّر** منطق أي استراتيجية: يعمل بعد حساب الإشارة، ومعطّل افتراضياً.

### توصيتي كخبير (تغيير إعدادات، لا كود)
1. **استخدم `scalping_i`** — مخارجها من ATR فتتكيّف مع التقلّب، وفيها شرط اتجاه EMA 30/50 أصلاً (وهو ما جعلها أفضل من المعكوسة في السوق الاتجاهي).
2. **ارفع الإطار إلى `1h` أو `4h`** — `/tf 1h`. الضجيج على 15m يبتلع الوقف.
3. **وسّع الوقف والهدف** بما يناسب الإطار: `/set sl 0.02` و`/set tp 0.04` على 1h أفضل من 0.9%/1.2%.
4. **فعّل فلتر الاتجاه** إن أردت تجنّب الشراء في الاتجاه الهابط: `/set trend ema`.
5. **قلّل مدة صلاحية الإشارة** حتى لا تدخل متأخراً: `/set ttl 300`.
6. **قِس قبل أن تثق**: `scripts/backtest.py` على بياناتك الحقيقية ثم قرّر.

## 🔒 الصرامة: الاستراتيجية التي تختارها تُطبَّق كاملة

ما دمتَ اخترتَ استراتيجية، تُطبَّق **كما هي** — لا خلط ولا تراجع صامت:

| الحالة | قبل | الآن |
|---|---|---|
| اسم استراتيجية غير معروف في `config.toml` | يعمل بغيرها **بصمت** | ❌ يُسجَّل خطأ ويظهر تحذير في `/strategy` ورسالة الإقلاع |
| `/set exit percent` مع `scalping_i` (تفرض ATR) | تُستخدم نسب ثابتة لا تنتمي للاستراتيجية | 🔒 يُعاد إلى ATR ويُبلّغك |
| استراتيجية تفرض ATR ولم تُحتسب المسافة | فتح الصفقة بنسب ثابتة غريبة | ⛔ **رفض فتح الصفقة** ورسالة توضيحية |
| إشارة صادرة من غير الاستراتيجية المختارة | تُمرَّر | ⛔ تُرفض ويُسجَّل الخطأ |
| إشارة محسوبة على إطار غير المطلوب | تُمرَّر | ⛔ تُرفض ويُسجَّل الخطأ |
| عدد الشموع أقل مما تحتاجه الاستراتيجية | لا إشارات بلا سبب واضح | ⚠️ تحذير صريح في الإقلاع و`/strategy` |

### مفاتيح الصرامة
| `/set` | الافتراضي | المعنى |
|---|---|---|
| `follow_exit` | `true` | مخارج الاستراتيجية تطغى على `exit.mode` |
| `strict` | `true` | ارفض فتح صفقة بمخارج لا تنتمي للاستراتيجية |

لتجاوز واعٍ (غير مُستحسن): `/set follow_exit false` ثم `/set exit percent`.

### ⏱ صرامة الإطارات الزمنية
- كل قراءة للإطار تمرّ عبر `Config.effective_timeframe()` — **لا تُرجع قيمة مرفوضة أبداً**.
- تُصلح `4` → `4h`، و`1mo` → `1M`، وأي قيمة مستحيلة → `15m`، ويُحفظ التصحيح.
- **تعديل `config.toml` يدوياً أثناء عمل البوت** يُصحَّح عند أول `reload()` (كان يُقرأ كما هو ويوقف الإشارات).
- إطار خاطئ **لا يوقف البوت أبداً** — قاعدة ثابتة منذ الإصدار السابق.

## 📓 استراتيجية Scalping Modified I — مطبَّقة حرفياً

منقولة سطراً بسطر من `01_Strategy_Scalping_Modified_I.ipynb` بلا أي تغيير في الثوابت أو المنطق.

### المؤشرات (كانت `pandas_ta`، الآن حساب خالص ببايثون — بدون numpy/pandas)

| في الدفتر | هنا | الثوابت |
|---|---|---|
| `ta.ema(Close, length=50)` | `ema(close, 50)` | `EMA_slow = 50` |
| `ta.ema(Close, length=30)` | `ema(close, 30)` | `EMA_fast = 30` |
| `ta.rsi(Close, length=10)` | `rsi(close, 10)` | للعرض فقط (الدفتر علّق استخدامه) |
| `ta.bbands(Close, length=15, std=1.5)` | `bbands(close, 15, 1.5, ddof=1)` | `BB_LENGTH=15`، `BB_STD=1.5` |
| `ta.atr(High, Low, Close, length=7)` | `atr(h, l, c, 7, mode="rma")` | `ATR_LENGTH=7` |

### قواعد الدخول (كما في الدفتر تماماً)

```python
# EMA Signal — النافذة [current-7, current) لا تشمل الشمعة الحالية
if   all(EMA_fast < EMA_slow): trend = 1      # هابط
elif all(EMA_fast > EMA_slow): trend = 2      # صاعد

# Total Signal
trend == 2 and Close <= BBL  →  شراء (long)
trend == 1 and Close >= BBU  →  بيع  (short)
```

### المخارج (من صنف `MyStrat` في الدفتر)
```
slcoef = 1.1        TPSLRatio = 1.5
شراء: SL = Close − 1.1×ATR   TP = Close + 1.1×ATR×1.5
بيع : SL = Close + 1.1×ATR   TP = Close − 1.1×ATR×1.5
```
أي **العائد : المخاطرة = 1.5 : 1** دائماً.

### تفاصيل دقيقة حوفظ عليها
- نافذة الاتجاه `iloc[start:end]` **حصرية** → آخر 7 شموع قبل الحالية.
- الانحراف المعياري لبولينجر بـ `ddof=1` (سلوك `pandas_ta` التلقائي = الانحراف المعياري للعيّنة).
- `ATR` بتنعيم `rma` كما يعرّفه `pandas_ta` (يتطابق مع الحساب الخالص بفارق ~1e-12).
- حجم الصفقة في الدفتر `mysize = 3000` وحدة للاختبار الخلفي؛ أما البوت فيستخدم `trade.qty_usdt` (قيمة بالدولار).

### تحقّق من القيم بنفسك
```bat
.venv\Scripts\python.exe scripts\strategy_check.py BTCUSDT --strategy scalping_i
```
يعرض EMA/بولينجر/ATR/RSI على آخر 3 شموع حقيقية + الإشارة + أسعار الوقف والهدف،
لتقارنها مع TradingView.

> اختبار آلي (`tests/test_scalping_i.py`) يعيد تنفيذ منطق الدفتر كاملاً بـ pandas

## ⏱ تغيير الإطار الزمني (ولماذا لا يتغيّر أحياناً)

```
/tf 5m          ← الأسرع
/set tf 1h
```

| الصيغة المقبولة | النتيجة |
|---|---|
| `5` · `5m` · `5min` · `5M` | `5m` |
| `15` · `30` | `15m` · `30m` |
| **`4`** · `6` · `8` · `12` · `24` | **`4h`** · `6h` · `8h` · `12h` · `1d` |
| `1h` · `1H` · `1hour` · `60` | `1h` |
| `4h` · `240` · `1d` · `1day` · `1w` · `1M` (شهر) | كما هي |

> الرقم العارٍ يُقرأ **دقائق** إن كان إطار دقائق مقبولاً (`5` → `5m`)،
> وإلا **ساعات** (`4` → `4h`، `24` → `1d`) — لأن `4m` و`24m` غير موجودين أصلاً.

الإطارات المسموحة: `1m 3m 5m 15m 30m 1h 2h 4h 6h 8h 12h 1d 3d 1w 1M`

**وقيمة خاطئة لا توقف البوت أبداً:** تُصحَّح تلقائياً ويستمر التشغيل مع تحذير واضح:
```
تحذير | تم توحيد الإطار الزمني: 4 → 4h
تحذير | الإطار الزمني "7m" غير مدعوم — تم استخدام 15m بدلاً منه واستمر البوت.
        المسموح: 1m, 3m, 5m, 15m, 30m, 1h, 2h, 4h, 6h, 8h, 12h, 1d, 3d, 1w, 1M
```
ويُكتب التصحيح في `config.toml` حتى لا يتكرر.

### لماذا قد يبدو أن الإطار «لا يتغيّر»؟

| السبب | الحل (مُعالَج في هذا الإصدار) |
|---|---|
| **فترة السمومية** (`cooldown_seconds = 1800`): الرموز التي أعطت إشارة كانت مستثناة 30 دقيقة، فلا يظهر أثر الإطار الجديد | ✅ `/tf` **يمسح السمومية تلقائياً** في نفس اللحظة |
| **تعديل `config.toml` يدوياً أثناء عمل البوت**: الإعدادات كانت تُقرأ مرة واحدة عند الإقلاع | ✅ `/reload` — أو **تلقائياً**: يفحص البوت تغيّر الملف في كل دورة فحص ويعيد قراءته |
| **إطار مرفوض** (`7m` مثلاً): تفشل كل طلبات الشموع ويُسجَّل الخطأ في `DEBUG` فقط، فلا تظهر أي إشارة ولا أي خطأ | ✅ يُرفض عند الإدخال + إن فشل **كل** الرموز يظهر تنبيه صريح في السجل وتليجرام |
| لا توجد إشارة أصلاً على الإطار الجديد | طبيعي — جرّب `/set both false` أو `/scanall` |

تحقّق من الإطار الفعّال الآن:
- `/tf` (بدون قيمة) → الإطار الحالي + عدد الرموز داخل السمومية
- `/status` → سطر `الإطار الزمني`
- `/settings` → `strategy.timeframe`

## 🧠 الاستراتيجية

### RSI (مؤشر القوة النسبية)
```
شراء:  RSI[-3] < 30  و  RSI[-2] < 30  و  RSI[-1] > 30   (اختراق صاعد من تشبّع بيعي)
بيع:   RSI[-3] > 70  و  RSI[-2] > 70  و  RSI[-1] < 70   (كسر هابط من تشبّع شرائي)
```

### Williams %R
```
شراء:  W%R < -99.5                                   (تشبّع بيعي شديد)
       أو  W%R < -75 ويتقاطع صاعداً فوق EMA(24)
بيع:   W%R > -0.5                                    (تشبّع شرائي شديد)
       أو  W%R > -25 ويتقاطع هابطاً تحت EMA(24)
```

### الدمج (التأكيد المزدوج)
`strategy.require_both: true` → **يجب** أن يتفق المؤشران، وأي تعارض يُلغي الصفقة.

### حماية الصفقة
- TP/SL تُوضع كأوامر `TAKE_PROFIT_MARKET` / `STOP_MARKET` مع `closePosition=true`
  (أي تغلق كامل الصفقة تلقائياً عند التحقيق).
- إن فشل وضع **وقف الخسارة** → يُغلق المركز فوراً حمايةً للمال.

> ⚠️ **تغيير Binance (ساري منذ 2025-12-09):** الأوامر الشرطية انتقلت من
> `POST /fapi/v1/order` إلى **`POST /fapi/v1/algoOrder`**، واسم حقل سعر
> الإطلاق تغيّر من `stopPrice` إلى **`triggerPrice`**. الإرسال للنقطة القديمة
> يُرجع `-4120 Order type not supported for this endpoint` وتُفتح الصفقة
> بلا حماية. هذا المشروع يستخدم النقطة الجديدة (مع محاولة احتياطية
> بـ `quantity + reduceOnly` إن رُفض `closePosition`)، ويلغي الأوامر الشرطية
> عبر `DELETE /fapi/v1/algoOrder` عند إغلاق الصفقة حتى لا تُفتح صفقة لاحقاً
> بالخطأ. للتحقق بنفسك: `/protect` أو
> `.venv\Scripts\python.exe scripts\check_protection.py`

| `DLL load failed` مع numpy/pandas | **مُصلح**: لم تعد المشروع يستخدمهما — حدّث بـ `update.bat` ثم احذف `.venv` وأعد `setup.bat` |

| `(-4120) Order type not supported for this endpoint` | **مُصلح**: نقلت Binance الأوامر الشرطية إلى نقطة Algo — حدّث بـ `update.bat` |
| `Can't parse entities: unsupported start tag` | **مُصلح**: رموز `<` و `>` في أسباب المؤشرات تُهرَّب الآن، وإن فشل التنسيق يُعاد الإرسال كنص عادي |
| `maximum number of running instances reached` | مجرد تحذير: دورة فحص سابقة لم تنتهِ. ارفع المدة بـ `/set interval 300` |
| `الإطار الزمني "..." غير مدعوم` | **مُصلح**: يُصحَّح تلقائياً (`4` → `4h`) ويستمر البوت — لم يعد يرفض التشغيل |
